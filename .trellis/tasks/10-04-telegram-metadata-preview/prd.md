# Telegram 元数据预填可行性验证

## 目标
用户粘贴 Telegram 消息链接，读取该消息及有限关联文本，将作者、漫画名、简介、标签预填到现有表单并允许修改。

## 已确认
用户选择“粘贴链接时预填”。样例网页 embed 返回内容限制，不能通过 HTTP 200 认定正文可读。现有项目无 Telegram 凭据或会话配置。实际应用创建请求返回通用 ERROR，用户要求同时调查免个人 API 申请和完整下载/解析工具；已完成七个候选的比较，优先建议 tdl 二维码登录验证。

## 验证要求
仅通过用户明确配置的凭据建立连接；不读现有客户端秘密、不发送消息、不加入频道、不下载附件、不变更账号敏感设置。先验证目标消息与小窗口正文可读，记录关联证据；失败明确呈现。session 和 api_hash 不进 Git、日志或聊天。

## 候选方案
验证阶段首选 tdl CLI 独立会话导出，备用为官方 Desktop JSON 导入；长期候选 Go 用户 MTProto adapter（gotd/td 为第三方库），通过 channels.getMessages 与有限 messages.getHistory 读取。详见 research/open-source-options.md。规则解析优先显式关联、标题和文件名；无依据字段留空，有歧义让用户选择。entities 使用 UTF-16 offset。首版不引入 OCR/LLM、持续监听或自动下载。

## 完成标准
- 可在本机安全建立项目专用的独立账号会话；tdl 路径无需自建 API 应用。
- 用目标链接完成一次真实只读请求；确认或明确说明账号访问限制。
- 验证来源文本与文件消息关联，再细化表单接入实现。

## 未决依赖
只读验证已完成：10 条样本消息、目标及关联帖、四字段解析、既有 ComicInfo 输出均通过。正式表单/API 尚未实现；其他频道和目标为附件帖的输入仍需扩展验证。详见 research/live-probe.md 与 design.md。
