# 作品处理向导与识别体验优化

## Goal

让用户从添加素材到生成作品、进入作品库按实际工作顺序完成操作：系统自动准备下一步，用户可以返回修正，仅在需要判断时介入。以用户提供的 Telegram 截图复现识别问题，将识别准确性和操作负担分别形成可验收要求。

2026-10-07 用户选择：**系统自动准备，最后保留一次“确认并开始”**。自动化止于可编辑核对稿；即使无冲突也不自动提交作品任务。用户于同日明确“确认实施”，任务进入 in_progress。

## Requirements

### R1 / P1：分步完成，返回不丢内容

流程：**添加素材 → 自动准备 → 核对并开始 → 处理结果**。自动准备是进度状态，不是另一个表单。单工作区承载独立页面式步骤；上一步保留来源、图序、OCR校对、候选及人工修正。未变化输入不重跑，用户返回后迟到结果不抢页面。成功提交后自动显示当前任务进度，返回查看不再次提交。

### R2 / P1：默认准备，集中处理不确定项

沿用已保存模型/服务和启用来源；常用提取字段包括标题、别名、作者、译者/汉化组、简介、标签。语言、字段集合、来源细选放高级选项。聚合建议为一份核对稿，相同值合并证据；有直接证据、空值、无矛盾且未手改的字段可默认预填，仅冲突/缺失实际来源/人工保护替换要求决定。

书目检索词由标题/别名准备；无匹配可跳过，禁止自动采用首条近似作品。已配置服务默认参与自动准备，入口明确说明外发范围（文字到已保存AI、标题/别名到启用源，图片本地），允许关闭；不再增加逐引擎确认弹窗。旧每次手选/确认的交互条款随本次决定显式更新，管理员与一致性边界保留。

核对页集中展示作品信息、真实来源和交付目标。用户可编辑或返回，最终点击一次“确认并开始”授权当前快照的作品处理与所示交付；无需再逐候选点击“采用”。存在未解决冲突时在同页处理，不能默认跳过冲突完成提交。

### R3 / P1：分层改进识别

保留原图/原文并建立派生文本映射；有限处理中文内部空白、跨行、聊天区域，不能全局删空格/数字/括号。完整caption优先于截断文件名；区分标题、英文别名、作者、汉化团体，角色配对不得归作者/系列，界面元素不得进书目字段，摘要不得越过正文边界。

AI语义说明、字段集合、输出预算共同评估；证据/类型验证保留，不用降低校验来掩盖失败。无结果与失败区别展示，可只重试失败环节；AI/来源不可用时能手动继续。

### R4 / P1：保护用户修正与异步一致性

沿用共享draft、字段锁/clear、输入/字段/设置版本与preflight；新流程步骤不替代Task Core状态。取消、返回、输入变化、401、离页清理有明确行为。草稿仅本次内存会话，不把原文写入URL、localStorage或htmx历史。

### R5 / P2：提交与交付闭环

保留Telegraph/归档来源，允许先截图再补来源。最终确认前只保留来源输入/本地文件引用及识别草稿，不调用会创建任务的upload init、下载或Komga写操作。提交绑定用户核对的草稿、来源和目标；确认后若该快照变化，须回核对页重新确认。重复点击或响应丢失不得重复创建任务。

Komga copy目前仅复制文件（`internal/httpapi/taskcore_handlers.go:278`；`internal/app/tasks/komga_copy.go:32`），结果必须区分已复制、待收录、已可见；仅真实book ID/元数据读回后称已收录，可从失败阶段续跑。

此前2026-10-05用户明确移除首页Telegram消息下载入口（`.trellis/tasks/10-04-media-workspace-integration/prd.md:1`），本任务保持该决定；截图来自Telegram不等于恢复下载入口。已有Komga编辑器继续复用。
