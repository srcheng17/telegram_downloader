## 当前截图指出的具体问题

1. 1440px 任务表前七列宽度合计100%，第八「操作」列被挤出视野；成功状态曾因类名差异不可见（后者v2已修）。
2. 390px 设置七个横向 Tab 中「连接」「安全」没有明确入口，选中项也会在可视范围之外。
3. 手机新建页中可选的简介、标签、题材、别名及每字段状态撑长页面，主要提交动作在数屏之外。
4. 桌面收起侧栏后仍占64px，只留下图标；用户要求的隐藏可明确实现为0px，页头开关负责恢复。
5. 设置页卡片相互嵌套，桌面可用宽度利用不足；来源与连接页尤为明显。

## 实施与验收

- 保留藏书工具的冷静石墨/蓝白色，而非引入远程字体或营销首屏。统一标题、正文、辅助文字和边界的层级，删去无业务用途的容器边框。
- 桌面侧栏展开224px/隐藏0px，主区即时获得宽度；隐藏时不可键盘聚焦，页头按钮始终可见并可还原。手机依旧用抽屉，桌面偏好不改变手机状态。
- 任务表在1440px内容区展示「操作」列及已完成任务的按钮；宽度由八列共享，长ID/URL可折行；手机只在表格自身滚动，页面不横溢。不删任务详情、错误或既有操作资格。
- 设置手机 Tab 改为7项全部可见的紧凑两行布局，桌面保留单行；Tab的role、箭头/Home/End键及hash深链不变。设置内部删掉重复的外内边框，保持各区块保存/测试反馈。
- 新建页首屏保留来源/标题/作者/册号，可选简介/标签/题材/别名移入同一个按需展开分组，所有字段仍属于同一元数据文档。手机提交区保持可找到，表单校验/错误反馈不能被固定元素遮挡；保留原有清空、人工保护和历史采用语义。
- 对比1440、390、360、768四种宽度，检查200%缩放、焦点、无横向溢出、Tab草稿/连接敏感内容清理、任务操作按钮和真实合成上传，输出修订后截图。

整合审查补充：新建页按来源→作品信息→采集信息→提交排列 DOM。桌面元数据在左、采集在右，手机同序纵向排列，避免 CSS `order` 造成焦点与视觉顺序冲突。手机导航按钮与来源切换的可点按区域至少 44px；抽屉宽度受视口限制，180px CSS 视口中关闭按钮仍可见。主导航同步 `aria-current="page"`。
