# 多图本地 OCR 与单作品元数据契约

> 范围更新：用户已明确元数据可扩展、来源及授权可配置；当前契约以 [父设计](../design.md) 为准。研究中的七字段实测仍只代表历史样例，不是扩展字段验收。

状态：规划。本轮只更新需求与设计依据，未实现或验证真实图片 OCR。

## 用户确认

- 使用 MiniCPM5-2B Q4_K_M 作为首选 AI 模型；当前 RackNerd alias 为 `minicpm5-2b-q4`。接口配置、模型发现与用户选择仍保留。
- 可以输入多张图片，全部属于同一作品，合并成一份可扩展元数据。首版不自动拆分作品或创建多个下载任务。

## 最小交互方案

1. 专用截图区域支持连续粘贴、一次粘贴多图、文件多选。普通文本输入框的粘贴行为保持原样；只有接收有效图片的专用区域处理图片事件。
2. 每张图有稳定 ID、缩略图、顺序和独立状态；支持放大、移除、上移/下移、失败重试。文件选择和粘贴使用同一校验/队列入口，截图不进入现有归档上传接口。
3. 一个 OCR worker 逐张处理，限制单张解码后的像素、文件大小及整批总量。具体数值通过代表性桌面/移动端截图试验确定；不因支持多图而并行创建任意数量 worker。
4. 分别保留每张原始 OCR、可编辑文字及其版本。成功图片按用户顺序形成合并预览；显示未完成/失败图片，用户明确选择采用部分结果后才以该部分生成候选。
5. 规则与用户主动触发的 AI 都针对当前合并文字生成同一作品的候选，不直接提交任务；用户核对本次元数据后，才使用独立输入的下载来源发起任务。

## 合并与证据保留

- 原始 OCR 永不因合并去重而删除，预览保留逐图来源，用户可回到具体图片校对。
- 完全相同图片可在识别前提示重复；仍允许用户保留。前后图相同边界行可提示重叠范围，由用户确认去重，不做全局模糊去重或擅自删相似段落。
- 跨图简介按用户顺序提供拼接预览，保留段落边界，不自动润色、概括或改变原意。
- 规则提取中的多个不同作者/标题/序号作为冲突候选展示，不“最后一张优先”。简介拼接、标签去重也必须能从原文核对；未知占位和不确定 OCR 不能被当成已确认事实。
- AI 的 JSON Schema 只保证格式，不保证语义或冲突检测完备。结果须通过当前字段注册表生成的白名单、类型/长度、现有元数据规范及候选来源检查；不能把模型自行挑选的值称为已消除冲突。

## 状态与异步边界

- 图片身份不依赖数组索引。OCR 结果必须同时匹配图片 ID、该图识别轮次和页面生命周期；被移除图片及旧重试的回调一律忽略。
- 图片增删/排序、单图编辑、重试替换文字均更新输入版本；规则/AI 请求携带该版本及字段版本快照。输入或服务/模型配置变动后，旧候选失效，迟到结果不得写入当前候选或表单。
- 合并预览是可追溯的派生结果，以逐图可编辑文字为唯一来源；用于 AI 的可编辑发送草稿只是本次请求快照，不能反向成为第二份合并原文。用户编辑发送文字后，后续 OCR 不能自动覆盖；源图片变化时标记发送草稿过期，提供查看差异和明确重新生成入口。
- 字段脏状态逐字段跟踪；自动预填只作用于没有用户改动的空字段。用户主动清空、采用候选及历史回填同样推进字段修订号。已有规则/AI 值的刷新以候选形式呈现，由用户选择采用；即便旧值与新值相同也不能借机清除脏标记。
- 一个图片失败不清空其他图片。取消只停止待处理队列和当前识别，保留已完成结果/手工编辑；重试只处理用户指定图片。
- OCR/AI 操作各有独立取消控制器，取消识别不能卸载整个页面或取消下载。页面卸载取消待处理队列、终止 worker、撤销预览 URL、取消规则/AI 请求并失效所有回调；切页前保护未提交草稿，不新增原图/OCR 持久化历史。
- 当前 `web/templates/base.html:27` 的 `hx-history-elt` 会纳入动态页面。新增 OCR 工作区须禁止 htmx 历史快照缓存敏感图片/文字，并验证返回导航；仅不写自定义 localStorage 并不足以满足“只在当前页内存”。

## MiniCPM 输入边界

当前模型服务上下文为 4096 token，包含聊天模板、提示、结构化字段契约和输出预留；不等于 4096 个汉字或全部可用于 OCR 的 token。模型调用采用 JSON Schema；普通提示输出在主对照里未满足严格 JSON 契约，见 [实测报告](racknerd-model-trial.md)。

多图先合并并校对再调用模型；明确显示本次实际发送的文字与目标接口。已知自托管模型在实现时验证完整提示的 tokenizer 预算检查及超限响应；通用接口使用有界请求与明确的上游超限反馈，不假装字符数是精确 token 数。无论前置检查或上游报错，均保留全部图片/文字/表单，不允许服务自动截断输入。首版不自动切块调用、扩容上下文或换模型；用户可缩减/选择发送文字，规则与人工填写始终可继续。

主对照的 512 输出 token 不是多图长简介的已验证上限。需按字段长度和输入预算验证输出空间；`finish_reason=length` 或结构化输出不完整时整份 AI 候选无效，保留先前草稿，不采用半份结果。

模型在 RackNerd 上部署不等于已接入产品；当前仅回环地址可访问，实际 Go 服务/容器的受保护连接仍需设计。OCR 必须在浏览器本地执行，图片不随 AI 请求发送。

## 验收场景

- 连续粘贴两张、多选数张、移除中间图、键盘重排，最终始终只有一份元数据；来源顺序和文字一致。
- 重复整图、上下重叠文本、跨图简介、作者/社团/翻译组及序号冲突，原文可核对且冲突不被静默覆盖。
- 第一张完成后第二张失败：明确显示部分完成，重试仅作用于失败图；用户仍可编辑和采用完成部分。
- 识别中移除/重试图片、添加图片、改变顺序：旧结果不归给错误图片，也不覆盖已编辑的逐图/合并文字。
- AI 请求途中修改单图文字、增删/排序图片、编辑字段或更改接口/模型：旧响应失效，用户输入保留。
- 超过单图/批次资源上限或 AI 输入预算：说明范围与恢复办法，已完成内容不丢失，无静默截断或自动外发。
- 卸载后迟到 OCR/AI 回调不改 DOM；worker 和预览 URL 释放。切页保护不等同于把敏感截图存入浏览器长期存储。
- 浏览器前进/后退与 htmx 历史恢复不残留原图/OCR 正文快照；用户主动清空字段后不能被任何迟到结果补回。
- AI 关闭、失败或拒绝时，仍可使用规则/手工元数据继续下载；上述方案不是已经测得的多图 OCR 准确率。
