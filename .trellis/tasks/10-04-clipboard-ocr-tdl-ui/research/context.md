# 已有证据与本轮方向

> 范围更新：用户已明确元数据可扩展、来源及授权可配置；当前契约以 [父设计](../design.md) 为准。研究中的七字段实测仍只代表历史样例，不是扩展字段验收。

## 用户方向变更

截图成为元数据来源；tdl 保留为附件下载及账号登录能力。旧 Telegram 元数据自动关联方案已验证可行，但不再作为本任务默认产品流程，不继续扩展频道专用规则。

## 已验证且可复用

- tdl v0.20.4 的独立二维码登录与目标消息读取已成功，不需要用户自行申请 api_id/api_hash。
- 登录时保留默认 reconnect backoff；自定义 20s 会与扫码后的连接重启路径冲突。退出 0 不足以证明授权，必须做真实账号/消息查询。
- 原始样例和 session 在仓库外私密目录，不能复制到本任务、测试 fixture 或日志。
- 元数据清洗、PostgreSQL JSONB 和 ComicInfo 已有完整链路；截图仅改变字段来源。
- 样例 ZIP 为 142.43 MiB，网页上传当前上限 64 MiB。Telegram 服务端下载的限制需要单独设计，不能假设现有上传通道可直接使用。

参考：[旧实测记录](../../10-04-telegram-metadata-preview/research/live-probe.md)、[元数据接口与字段保护草案](../../10-04-telegram-metadata-preview/design.md)。这两份是历史证据，发生冲突时以本任务用户需求为准。

## 前端接入证据

- `home/index.js` 的 mount/unmount 管理页面生命周期；专用 paste 处理器可以从 `event.clipboardData.items` 获取 image File，无需持续读取系统剪切板。
- 没有图片时不调用 preventDefault；普通文字粘贴保持浏览器行为。当前归档 file input 不能复用于截图。
- `home/state.js` 已采集七个元数据字段；历史回填会无条件覆盖并切换任务来源，不能直接用于 OCR 自动填充。
- 仓库没有 OCR、Canvas 或图片预览模块。当前 Vite 只有四个入口；新增 worker/WASM/语言资源须正确落在静态路由并进入 Docker 构建。
- `internal/httpui/handler.go` 当前静态资源设 no-store；语言模型的首次加载与缓存需实测，不能默认依赖公共 CDN。
- 现有下载/解包图像限制不等于 OCR 限制。截图需同时限制文件字节数和解码像素量，提供超时、取消和资源释放。

## OCR 候选的核实范围

- [Tesseract.js](https://github.com/naptha/tesseract.js)：npm 当前 7.0.0，Apache-2.0，支持浏览器 Web Worker/WASM、多语言、自定义同源资源路径和文本/blocks 输出。适合本地识字；本身不理解作者、作品名等业务字段。尚未用用户截图做精度/耗时实测。
- [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)：维护中、Apache-2.0；如采用服务器部署，需要另评估模型、依赖和资源，不直接引入当前 Go 服务。
- 用户已选择 OCR＋可配置 AI/规则。首版方案以本地 OCR＋规则为默认，AI 仅作为用户主动触发的文字结构化辅助，不默认发送截图；保留手工校对。当前项目没有 provider 配置，需新增受保护的服务端接入。
- R18 内容是否被拒绝及账号处理取决于具体提供方，未对任何提供方作兼容性承诺。拒绝、超时、限流、无效 JSON 均应保留原 OCR 和草稿；不自动重发拒绝内容或转投其他接口。
- 截图与 OCR 文字是不可信输入。AI 只提取当前注册并允许该来源提取的字段，不执行其中的指令；输出白名单/类型/长度校验后才能变成候选。生成简介不能替代原文校对。

## 不应沿用的假设

- 不再把“必须读取频道历史才能预填”作为前提。
- 截图不会提供真实下载链接；下载链接应由用户另行粘贴，不从截图中的短标题或“点击”文字猜测隐藏 URL。
- tdl CLI 有二维码终端流程不代表已提供可直接嵌入网页的登录 API，需要专门调研桥接及生命周期。
- 七项已完成运行逻辑修复仍属于原独立任务，不因新 UI 任务撤销或混入范围。
