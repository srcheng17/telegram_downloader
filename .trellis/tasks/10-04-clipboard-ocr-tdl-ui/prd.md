## 功能范围

### R0 可扩展元数据模型

- 以有版本的字段注册表管理标准字段和受限自定义字段，前后端编辑、校验、OCR/规则/AI 候选、书目映射、任务快照、历史和导出使用同一份定义，不能在各入口各自固定七字段。
- 首版除原有信息，还支持按角色区分的创作者/画师/译者、别名、出版社/品牌、出版日期、语言、阅读方向、年龄分级、书籍/系列计数、ISBN/其他来源标识、公共引用链接。页数从实际图片计算，未知日期精度和分级保留未知。
- 设置页支持注册/调整标签与约束/停用自定义字段，保留历史定义版本；支持有名称空间、类型和长度/数量限制的自定义字段；可编辑文字、整数、布尔及文字列表，不执行脚本，不允许任意字段改写请求目的地或打包路径。
- 每字段区分未提供、明确清空和已赋值，记录来源与修订、人工锁定；采集结果只是建议，用户确认后才进入事实元数据。冲突可对照解决，低可信来源不能覆盖人工输入。
- 保持旧七字段接口、旧任务和历史可读，通过适配器投影到新文档；新文档是唯一事实源。已创建任务持有字段/规则版本及元数据快照，之后修改来源、字段定义和授权不会悄悄改变已提交任务。
- 提交快照不被下载过程改写；原包补全及实际页数作为成功产物的派生元数据保存，历史清楚区分提交与产物版本。
- 标准外字段默认在应用内保存并清楚标记导出能力；导入中的未知元数据受 R7 的保留策略保护，原有七字段实测分数不能当作扩展字段准确率。

### R1 截图识别与元数据确认

- 专用区域支持连续粘贴剪切板图片、一次粘贴多张图片及选择多个图片文件；新图片追加到当前作品的截图列表，保留普通输入框的文字粘贴。
- 展示有顺序的缩略图、逐张识别进度、原始识别文字与可编辑文字；支持调整顺序、移除和单张重试，不要求每张图都重复填写元数据。
- 同一作品的全部有效截图按用户顺序合并为一份可核对的识别文字和一份可扩展元数据草稿。重复/重叠内容保留逐图原文供校对，合并时不得静默丢失简介或把相似文本误删；作者、标题、序号等字段冲突明确提示，由用户选择，不用后图无条件覆盖前图。
- 单图失败或取消时保留其他图的结果和用户修改，明确哪些图尚未纳入。允许用户移除/重试失败图或明确采用当前已完成结果，不把部分识别结果冒充全部成功。
- 图片文字识别与语义字段提取分开评估，不把 OCR 等同于能够理解任意频道排版。
- 保留作者、漫画名、系列名、序号、简介、标签、类型的便捷录入，并使用 R0 的可扩展字段模型；缺失或有歧义时留空/提示，不猜测。
- 用户可修改识别结果；追加/移除/重排图片、重新识别、迟到响应、历史回填和页面切换不能覆盖用户编辑。图片集合或识别文字变化后，旧规则/AI 候选标为待更新，不把其混入当前结果。
- 元数据识别不依赖 Telegram 账号，也不自动创建下载任务。
- 默认本地 OCR 后进行规则提取；无 AI 配置或关闭 AI 时，识别、编辑和下载仍可完整使用。
- 提供用户配置的 AI 接口作为主动触发的文字结构化辅助。首版不默认把截图上传给 AI；发送前可查看和修改 OCR 文字，明确本次发送给哪个已配置接口。
- AI 返回只作为当前注册且允许提取的字段候选，区分规则提取、AI 建议与用户修改；字段有证据才填写，不把未知信息补写成事实。
- AI 的内容拒绝、限流、超时、鉴权失败或无效结果均不清空现有 OCR/规则/手工结果，不阻塞后续下载。内容拒绝不自动重发或切换供应商。
- 保留识别原文供校对，AI 不擅自改写简介。截图/OCR 中的文字仅作为待提取数据，不能改变系统指令、调用工具或决定请求目的地。
- 原始 OCR 文字、可编辑的识别文字和表单草稿分开管理；截图及原文默认仅保留在当前页面，不新增原图/原文历史库。只有用户确认提交后的元数据进入现有历史。
- 规则可在设置页保存版本，改变规则使旧候选失效；规则以字段识别与映射为边界，可提供常用标签别名/匹配模板；不要求每个频道都配置模板，不引入可执行脚本或通用工作流引擎。
- 多图识别有单图字节/像素及批次总量边界，超限时明确反馈且保留已接收图片。合并文字超出所选模型的输入预算时，提示用户缩减/选择本次识别文字，不静默截断、不自动丢弃后面的图片或调用其他模型。

### R2 tdl 下载

- 支持用户提供 Telegram 消息链接，通过 tdl 下载附件，并与确认后的元数据一同进入现有处理链路。
- 对支持的归档格式复用解包、图片排序、CBZ、ComicInfo 和 Komga 功能。
- 下载状态、失败、取消、重试、限流和账号失效在页面可见，任务资格仍由 Task Core 决定。
- 明确下载目标选择、附件类型/体积、临时文件清理和重试语义；样例 ZIP 142.43 MiB，不能静默套用现有 64 MiB 浏览器上传限制而导致不可用，也不能无界放大内存/磁盘用量。

### R3 Telegram 账号页

- 在网页提供登录状态、扫码连接、二维码刷新/过期、可选两步验证、失败反馈及重新连接入口。
- 登录成功以服务端真实授权验证为准，不依赖 CLI 退出码或本地文件存在。
- session 仅保存在服务端私密持久化位置；不向网页暴露原始 session、api_hash 或运行日志。
- 实现前确认网页登录桥接方式、管理员访问边界及账号与下载进程的并发协调。

### R4 前端整体重设计

- 覆盖新建下载、任务列表/详情、Telegram 账号、设置及元数据历史入口。
- 主工作区突出“下载来源、截图识别、元数据确认、开始任务”；常用操作有清晰层级。
- 中文界面，桌面优先且适配移动屏幕，键盘操作、焦点、错误与加载状态完整。
- 现有 Telegraph 下载和本地归档上传默认保留；若后续调整其入口或范围，须在最终设计中明确。
- 复用 Go templates、原生 JavaScript、htmx、Vite；不因视觉更新默认更换前端框架。

### R5 AI 接口配置与模型发现

- 设置页提供 AI 启停、接口地址（Base URL）、API Key、模型选择和连接测试。优先兼容 OpenAI-compatible 接口，首选已部署的 RackNerd MiniCPM5-2B Q4_K_M，支持用户改为其他兼容服务；不因确定模型而自动发送 OCR 文字。
- 用户填写并确认接口地址及凭据后，以及打开已配置的 AI 设置时，由服务端自动请求该接口的模型列表，解析真实模型 ID，显示可搜索的选择列表；提供手动刷新。修改输入的过程中不逐字符请求，不自动选择第一项或悄悄替换当前模型。
- 模型列表加载、空列表、鉴权失败、不支持模型发现、限流和超时均有明确中文反馈。发现失败时保留已保存配置，允许手工填写模型 ID；模型列表读取成功与实际推理测试分别显示结果。
- 用户选择并保存模型后，解析使用该配置的准确模型 ID。刷新后已保存模型消失时保留原值并提示需核对，不能自动换模型；AI 内容拒绝也不触发切换。
- 地址或凭据改变时，旧的模型发现结果失效，旧请求迟到不能覆盖新列表或用户选择。不同服务的模型选择不能静默继承；接口主机变化时，不自动向新主机发送原服务保存的密钥。
- 列表本身不保证模型支持文字或结构化输出。有可靠能力信息时标注用途，明确仅支持图片/视频/embedding 的模型不可用于文字提取；信息缺失时标注待验证，不仅凭模型名字隐藏未知模型。提供固定无敏感样例测试选定模型的文字提取与输出契约，不自动发送当前 OCR 文字；测试结果绑定接口、凭据版本及所选模型，任一改变即失效。
- 凭据仅在服务端受保护保存，读取配置只返回是否已配置，不回显密钥；模型列表和推理调用均通过服务端，错误反馈不泄露上游正文、密钥或认证日志。

### R6 公开书目搜索与男同向漫画支持

- 增加可选的关键词搜索入口，用户可手工输入标题/作者，或从 OCR 候选提取关键词后确认搜索；不把整组截图、完整 OCR 原文或 Telegram 链接自动发送到书目服务。
- 按来源能力支持原文标题、中文译名、别名、作者及作品 ID/ISBN 检索；不支持的搜索方式明确提示，不假设每家都有相同参数。先搜索候选，再由用户选择正确作品及版本，逐字段预览差异后采用。
- 外部书目、OCR、规则和 AI 都只产生候选，不覆盖人工修改；保留采用字段的来源标识/原始分类供核对，采用版本化文档存储与 R7 定义的 ComicInfo 映射。来源故障、无结果或权限不足时仍可使用多图 OCR 和人工填写。
- 支持 BL、男同向漫画（gay manga/geikomi 等来源词）与同人志；题材、出版形式和年龄分级分别识别。保留原始标签及来源，不将所有相关词无条件合并，不因同性题材推断 R18，也不由标签推断作者或读者的性取向。
- 不同来源的成人内容开关、凭据要求和分级语义分别处理；权限不足、默认过滤与没有收录应有不同反馈。未知分级不能当作全年龄或已确认成人。
- 系列、单行本、短篇、合辑、同人志和译本需区分；作者、画师、社团、翻译组不混填。系列总卷数/最新卷数不能填为当前文件序号，出版书目不能直接替代特定同人志版本。
- 遵守所选来源的限流、署名及数据使用条款，仅按需检索，不镜像整站；开源聚合工具的代码许可证不代表上游元数据可以任意再分发。候选源与实测范围见 [公开元数据源调研](research/public-metadata-sources.md)。

### R7 可互操作的元数据封装与原信息保留

- 继续使用 CBZ 与根目录唯一的 UTF-8 ComicInfo.xml，保留原七字段兼容并支持注册扩展字段；以公开 ComicInfo schema、成熟读写工具及 Komga/Kavita 的实际消费行为确定格式，不将私有 JSON 变成必需的阅读器协议。
- 当前 Tags 属于 ComicInfo 2.1 草案扩展；导出必须明确适用配置并符合字段顺序，不能把含扩展的文件宣称为严格 2.0 合规，或无提示删除标签。R0 定义首版可选标准字段；没有 ComicInfo 映射的自定义字段在界面明确标注只保存在应用内，不强塞到其他标准字段。
- 读取已有归档元数据后再合并，未提供字段保留、用户确认覆盖与主动清空分开；不支持的字段明确提示并保留原件/原始元数据，不静默丢失。新增 CBZ 导入时须覆盖前端与实际上传/提取链路，不只修改文件选择器。
- 图片数量、字节内容与阅读顺序受保护；新包的页面名不产生同名冲突，旧包纯元数据更新若引入需另定保留 entry 的契约。元数据页索引必须对应最终页面顺序。
- 生成临时包后校验再发布；损坏输入、取消或写入失败不破坏原件和已成功产物。需要保留的原件及元数据副本登记持久引用，直至管理员明确删除，不随成功清理；损坏/重复 XML 首版停止并提示修正后重新提交，不能把元数据备份等同完整漫画备份。
- 书目公开链接与必要署名可以随元数据保存；凭据、Telegram session/令牌、截图和原始 OCR 不进入漫画压缩包。详细字段来源默认由项目内部保存。

### R8 采集源配置、授权与管理员登录

- 内置单管理员登录，不提供公开注册/多用户/RBAC；所有应用业务页、任务/文件和配置接口受保护，保留既有非敏感健康探针。管理员初始化凭据经本机私密配置提供，不设通用默认密码。
- 采集源按项启停、排序，展示能力、鉴权要求、内容筛选和连接测试状态。首版适配 MangaBaka、MangaUpdates、Bangumi；其他已调研源保留扩展接口，不同时承诺全部上线。
- 每个来源独立配置授权（无授权/API key/token 等按实际适配器支持），允许保留、替换、清除并验证。来源授权与 AI 凭据、Telegram 会话相互隔离，不跨来源复用或转发。
- 凭据在服务端受保护加密保存，主密钥独立于数据库；接口只回报是否已配置与测试状态，不回显密钥。失效/缺权限/速率限制需区分，不把认证错误当作无结果。
- 管理员写操作做会话与跨站请求保护，退出和密码变更能使旧会话失效；源配置更新令相关候选/连接测试失效，但不覆盖未提交的人工草稿。
- 来源优先级只决定搜索/展示及空字段建议顺序，不自动认定同名作品相同；用户明确搜索才向所选启用源发送关键词。采集与模型调用不隐式互相触发。

### R9 分批并行交付

- 本父任务统一需求、共享接口和最终验收；原 8 个子任务负责已批准的三批交付，Komga 存量元数据管理与 CLI/AI Skill 作为第 9、10 个独立子任务规划，不把原批次完成状态误报为新功能完成。
- 第一批并行完成元数据基础、授权/配置基础、现代化界面框架；第二批按依赖和空闲槽位推进多图 OCR/AI、书目源搜索、tdl 登录/下载、ComicInfo 往返；最后集中跨功能与阅读器验证。
- 同时最多 3 个实现工作单元，加 1 个集成/评审负责人。每个单元独占明确模块；共享路由/启动装配、迁移编号、构建产物和全链路回归由负责人串行接入，不让多个 worker 竞争同一文件。
- 已有运行逻辑修复仍属独立任务，不撤销、不混入新任务完成统计；旧频道历史解析仅留作研究证据，不重新扩展。

## 验收标准

- [ ] 标准新增字段及至少一个自定义字段走通编辑 → 采集候选 → 确认 → 任务快照/历史 → 再次读取；旧接口兼容，未提供/清空/赋值互不混淆。
- [ ] 无标准导出映射的自定义字段有清晰提示且在应用内保留，不被静默丢弃或写进错误 ComicInfo 字段。
- [ ] 来源可以独立启停/排序/配置授权，保存后重新打开仍正确；凭据保留/替换/清除、缺权限、过期、限流与跨源不转发通过验证。
- [ ] 未登录不能读取业务页、元数据、归档、源配置或 Telegram 登录事件；管理员登录/退出、CSRF 和旧会话失效有效，健康探针仍可用。
- [ ] 用户可连续粘贴、一次粘贴多张或选择多张同一作品截图，调整顺序/移除/单图重试后仍只生成一份可编辑元数据；普通文字粘贴不受影响。
- [ ] 包含重复截图、上下重叠、跨图简介和冲突作者/序号的脱敏样例可逐图核对；原文不丢失，冲突可选择，不能把不同来源的简介静默改写成新内容。
- [ ] 单张失败、识别中追加/移除/重排、编辑后重试、旧 AI 响应返回均不覆盖用户修改；部分完成状态与全部完成可区分。
- [ ] 不同排版的脱敏样例可评估字段准确性；作者/社团/翻译组不混淆，未知字段不自动编造。
- [ ] 不配置 AI 时，OCR → 规则/手工填写 → tdl 下载流程可用；AI 拒绝、失败或返回不合规字段时仍可继续，且不丢失草稿。
- [ ] 仅用户主动调用时向指定 AI 接口发送已确认的识别文字；默认不发送截图，不在日志记录正文或密钥。
- [ ] 识别文字包含指令式内容时，仅作为数据处理；AI 输出通过字段注册表生成的白名单、类型和长度校验。
- [ ] 配置兼容接口后，能自动读取模型列表、搜索选择并保存；重新打开设置后保留准确的模型 ID，实际提取请求使用用户选择的模型。
- [ ] 模型列表失败、空列表、不支持发现、选定模型消失和接口切换均有明确反馈；可手工填写模型 ID，旧响应不覆盖新配置，不发生自动换模型或向新主机转送原密钥。
- [ ] 能区分“模型列表读取成功”和“选定模型推理测试成功”；模型测试使用无敏感内容样例，不发送页面当前 OCR 原文。
- [ ] 首选 MiniCPM5 使用 JSON Schema 提取，实际请求的模型 ID 为已保存的 `minicpm5-2b-q4`；多图合并后输入超预算时明确反馈，不能静默截断或改用其他模型。
- [ ] AI 输出截断时不采用半份结果；主动清空字段也受编辑保护；浏览器/htmx 返回导航不残留敏感截图或 OCR 正文历史快照。
- [ ] 超限/损坏图片、连续粘贴、识别取消、迟到结果和切页均可恢复，无残留 worker 或草稿覆盖。
- [ ] 用户可从网页完成 Telegram 登录，并通过真实授权查询确认；失败、二维码过期、2FA 有明确状态。
- [ ] 一条真实 Telegram 归档附件走完 tdl → Task Core/worker → CBZ/ComicInfo → 下载或 Komga；记录文件体积及资源边界。
- [ ] 取消/重试/并发、会话失效、限流和临时文件清理通过有意义的回归验证。
- [ ] 新 UI 覆盖核心页面，并在实际构建镜像中验证资源、响应式和操作流程；同步提交 dist 产物。
- [ ] 原有 Telegraph 与本地上传链路没有功能回退。
- [ ] 可用手工关键词或已确认的 OCR 标题搜索书目，查看来源/别名/作者后选择并逐字段采用；外部搜索不发送截图、完整 OCR 或下载链接，不覆盖用户已编辑字段。
- [ ] 选用来源用普通漫画、BL、男同向漫画、同人志分别评估，报告样例命中与未覆盖范围；无结果、成人过滤、缺权限、超时/限流均可恢复。
- [ ] BL/男同题材、同人出版形式与成人分级互不替代；同名异作/不同版本需确认，总卷数不误填当前卷号，来源信息及必要署名可核对。
- [ ] 输出 CBZ 中只有一个根目录 ComicInfo.xml，按选定 schema 配置验证；保留 Tags 且版本说明准确，字段顺序符合规范。
- [ ] 已有元数据导入/编辑/导出后，未修改标准字段保持，主动清空可生效，未知/冲突字段不静默丢失；CBZ 文件可经完整输入链路处理。
- [ ] 对多目录同名图片、1/2/10 页序及损坏/取消样例，验证图片数量、顺序、哈希与 CRC，并确认没有半包或原件损坏。
- [ ] 在隔离 Komga/Kavita 中验证代表性 CBZ 的元数据读取，区分 XML 反序列化、XSD 合规和实际阅读器兼容；不宣称本轮源码调研已完成此验收。

## 暂不包含

- 按频道长期监听、扫描全部历史、为每个频道维护介绍帖关联规则。
- 将混合多个作品的截图自动分组、自动创建多个作品或批量下载任务。
- 自动加入频道、发送消息或更改账号敏感内容设置。
- 全面替换 Task Core、部署拓扑或前端技术栈。
- 本任务创建不包含提交、推送、合并或整套产品生产部署；用户后续明确授权的 RackNerd 小模型隔离部署/测试单独记录验证结果与资源边界。
