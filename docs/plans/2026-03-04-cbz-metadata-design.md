# CBZ 元数据与命名功能设计（Design）

## 目标
在下载界面新增可选元数据输入（作者、漫画名、书籍详情介绍、标签），生成带 `ComicInfo.xml` 的 `.cbz` 文件；文件名遵循 `作者_漫画名_时间戳.cbz`，并保证唯一；重复下载场景提供“生成新的CBZ”与“取消并下载已有文件”的分支交互。

## 已确认需求
1. 元数据由用户手动填写（可为空）。
2. 标签支持中文逗号 `，` 与英文逗号 `,` 分隔。
3. 生成 `ComicInfo.xml`，并写入 CBZ 包内。
4. ComicInfo 字段映射：
   - 作者 → `Writer`
   - 漫画名 → `Series` + `Title`（双写）
   - 介绍 → `Summary`
   - 标签 → `Tags` + `Genre`（双写）
5. 文件名：`作者_漫画名_时间戳.cbz`。
6. 作者/漫画名为空时使用占位符。
7. 命中已有成功下载时，先提示用户选择：
   - 生成新的 CBZ（强制新建）
   - 取消并下载已有文件（不新建）
8. 前端页面除项目名外统一中文。

## 方案选择
采用方案 B（重复检测后二次确认）：
- 首次提交做 URL 查重。
- 命中已有成功文件时返回确认态，前端展示双按钮。
- 用户确认后再以 `force=true` 发起新任务。

## 交互设计
### 首页下载区
- 将现有英文文案改为中文。
- 新增元数据输入区（均非必填）：
  - 作者
  - 漫画名
  - 书籍详情介绍（多行）
  - 标签（提示“支持中英文逗号分隔”）

### 重复命中确认
后端返回 `duplicate=true` 且 `needs_confirmation=true` 时：
- 展示提示：该文件已有下载，是否生成新的 CBZ 文件？
- 按钮一：生成新的CBZ（继续提交，`force=true`）
- 按钮二：取消并下载已有文件（直接使用 `download_url`）

## 后端设计
### 路由层（/download）
- 接收新增字段（form/json）：
  - `author`
  - `comic_name`
  - `summary`
  - `tags`
- 保留去重逻辑，但在命中成功缓存时返回确认态载荷（不立即新建）。
- 用户确认后再次提交 `force=true`，触发新建任务。

### 任务存储（SQLite）
在 `tasks` 表新增字段并兼容迁移：
- `author`
- `comic_name`
- `summary`
- `tags_raw`
- `tags_normalized`
- `result_cbz_path`（沿用现有字段也可，最终保持兼容）

> 兼容策略：旧任务无新字段时按空值处理。

### 下载服务
- 以任务元数据参与产物生成。
- 构建 `ComicInfo.xml` 写入临时目录，再整体打包。
- 输出文件扩展名改 `.cbz`。
- 文件名规则：`作者_漫画名_时间戳.cbz`。
- 占位符建议：
  - 作者：`未知作者`
  - 漫画名：`未命名漫画`

### 标签规范化
- 输入先统一替换 `，` -> `,`
- 按 `,` 分割
- `strip()` 去首尾空白，过滤空标签
- 再用英文逗号拼接为 `tags_normalized`
- 同值写入 `Tags` 与 `Genre`

## 数据流
1. 用户输入 URL + 元数据并提交。
2. 后端查重：
   - 无重复：创建任务并下载。
   - 有重复成功：返回确认态。
3. 前端用户选择：
   - 生成新的CBZ：再次提交（`force=true`）。
   - 取消并下载已有：直接跳转下载。
4. 下载线程抓图、生成 `ComicInfo.xml`、打包 `.cbz`。
5. 日志页可下载该 `.cbz`。

## 错误处理
- 元数据为空：允许，写空字符串；作者/漫画名仅用于文件名时采用占位符。
- 标签全部为空：`Tags`/`Genre` 写空。
- `ComicInfo.xml` 生成失败：任务失败并清理临时文件/保留策略与现有一致。
- 重复命中但原文件丢失：回退为新建任务（现有机制延续）。

## 测试设计
- Web/API：确认态响应与 force 提交流程。
- Integration：
  - 重复→取消并下载已有（不新建）
  - 重复→生成新的CBZ（新建任务）
- Repository：新增字段持久化与迁移。
- Service：
  - `.cbz` 后缀
  - `ComicInfo.xml` 存在与字段值
  - 标签规范化
  - 文件名占位符与时间戳规则

## 非目标
- 不引入自动抓取作者/标签。
- 不在本次改动中新增多语言切换，仅固定中文文案（项目名除外）。
