# 前端元数据分隔符标准化设计（作者/标签/类型）

## 目标
在不改变现有前端界面的前提下，提升元数据输入容错：
- 作者支持中英文逗号分隔；
- 标签与类型支持中英文逗号、空白字符、`#` 分隔；
- 所有字段统一输出为英文逗号连接的规范字符串，去除无效项与重复项。

## 范围与约束
- **范围**：`/download` 提交链路的输入标准化（前端帮助文案 + 后端解析）。
- **不做**：不改页面布局、不改交互结构、不新增字段。
- **兼容性**：保持原有仅逗号输入场景行为不变。

## 规范化规则

### 1) 作者（author）
- 分隔符：仅 `,` 与 `，`
- 规则：分割后对每个条目 `trim`，移除空项，按首次出现顺序去重
- 输出：英文逗号连接

示例：
- 输入：`" 张三, 李四，张三 "`
- 输出：`"张三,李四"`

> 说明：作者中的空格仅用于条目前后清理，不作为分隔符。

### 2) 标签（tags）/类型（genres）
- 分隔符：`,`、`，`、任意空白（可多个）、`#`
- 规则：分割后 `trim`，移除空项，按首次出现顺序去重
- 输出：英文逗号连接

示例：
- 输入：`" #科幻  冒险，连载#热血  "`
- 输出：`"科幻,冒险,连载,热血"`

## 架构方案
采用 **后端统一标准化 + 前端文案提示**：
1. 前端继续提交原始文本；
2. 后端在 `extractFromMap` 统一解析并规范化；
3. 规范结果写入 `author`、`tags_normalized`、`genres_normalized`；
4. `tags_raw` 与 `genres_raw` 保留原始（trim 后）输入。

该方案集中治理、回归风险低，且不会改变界面。

## 代码改动点
- `go-backend/internal/httpapi/api.go`
  - 新增 author/tag-like 标准化辅助函数；
  - 在 `extractFromMap` 应用不同字段规则。
- `templates/index.html`
  - 更新字段帮助文案，明确分隔规则。
- `go-backend/internal/httpapi/api_test.go`
  - 新增/调整单测覆盖分隔、trim、去空、去重、保序、兼容性。

## 测试策略
- 单元测试（必做）
  - 作者仅按中英文逗号拆分；
  - 标签/类型按逗号+空白+`#` 拆分；
  - 去重保序；
  - 老输入格式回归通过。
- 集成回归（可选）
  - 复用现有 `go test ./...` 与前端 e2e 流程，确认无副作用。

## 风险与缓解
- 风险：分隔正则过宽导致意外切分。
- 缓解：
  - 作者与标签/类型使用不同函数（避免过度复用导致规则串味）；
  - 为边界样例（多空格、连续分隔符、前后分隔符）补专门测试。

## 验收标准
- 作者：仅逗号拆分并规范输出；
- 标签/类型：支持逗号+空白+`#`，规范输出；
- 三字段均实现：`trim + 去空 + 去重(保序) + 逗号拼接`；
- 前端界面结构不变，仅文案更新；
- 现有提交流程与测试通过。
