# Komga 存量作品编辑与恢复

「作品库」读取已获准的 Komga 书库，选择 CBZ 后可预览字段变更，再写回该文件根目录的 `ComicInfo.xml`。保存还会请求 Komga 重新分析并核对当前元数据；文件写入与 Komga 读取是两个独立阶段，页面分别显示结果。此功能只处理已映射且可安全写入的 CBZ，不负责移动作品或修改 Komga 的系列级元数据。

## 部署与连接

1. 将书库在 Komga 容器内的根路径，以读写方式挂载到本项目 API 容器。API 运行用户必须能读写 CBZ 所在目录，并能在同目录创建临时文件。多个书库需分别增加挂载；worker 不执行存量作品编辑。
2. 在部署环境设置 `KOMGA_LIBRARY_MAPPINGS`，把 Komga 的书库 ID、Komga 容器内根路径和 API 容器内挂载路径一一对应。例如：

   ```json
   [{"library_id":"example-library-id","komga_root":"/books/comics","local_root":"/app/komga-books"}]
   ```

   `komga_root` 必须与 Komga 返回的该书库根路径完全一致；`local_root` 必须是同一批文件在 API 容器中的绝对路径。浏览器请求不能指定挂载路径。未映射书库如需只读浏览，可把其 ID 放入 `KOMGA_READONLY_LIBRARY_IDS`，例如 `["another-library-id"]`；同一 ID 不能同时出现在两个配置中。默认两项都是空数组，因而不会暴露书库。
3. 为 `KOMGA_EDIT_BACKUP_ROOT` 配置书库目录外的持久存储。Compose 默认 `/app/komga-edit-backups`，使用独立卷。首次启动会以 `0700` 创建不存在的目录；已有目录不会被自动改权限，必须预先让 API 用户拥有并可写。备份根及每次操作的目录仅允许所属用户访问。不要把备份卷放到 Komga 扫描路径、静态资源目录或构建上下文中。
4. 在「设置 → 连接」保存 Komga 地址和 API 密钥，再测试连接。密钥由服务端加密保存，不会返回浏览器。连接默认要求 HTTPS；只有显式允许不安全 loopback 时，才接受本机 HTTP。书库需启用 ComicInfo 书籍元数据导入，作品媒体状态需为 `READY`，相关字段不得被 Komga 锁定。条码 ISBN 导入开启时不能清空 ISBN。

修改映射或挂载后，先在「作品库」核对书库是否显示为可写，再选一份测试 CBZ 检查详情中的可编辑状态。文件、路径或 ZIP 结构不满足安全检查时，详情会给出只读原因；不要通过放宽挂载权限或手工改数据库来绕过检查。

## 保存与状态判读

在作品详情中修改字段，先查看差异预览，再保存。预览令牌有效期为 10 分钟，绑定文件版本、字段定义及 Komga 当前元数据；此期间任一项变化都需要重新读取和预览。原 `ComicInfo.xml` 的页数与实际图片数不符时，详情会提示单独确认修正；确认后可仅修正页数，不必同时修改其他字段。未确认时不会写回该归档。

服务端先在私密卷保存并校验完整原件，再在原文件目录原子替换 CBZ。保存响应包含 `operation.id`；后续可用页面的操作状态或 `GET /api/komga/edits/{operationId}` 查询。`file_committed` 表示新 CBZ 已写入，`projection_consistent` 表示 Komga 当前回读与目标字段一致，`analyze_verified` 只在观察到可归因的非清空字段变化时为真。Komga 接受分析请求、返回 `READY` 或清空字段的 PATCH 成功，单独都不构成导入已完成的证据。

| 状态 | 含义与后续动作 |
| --- | --- |
| `preparing` / `prepared` | 正在备份或准备替换；重启后会有界核对并恢复操作记录。 |
| `file_committed` / `sync_pending` | 文件已写入或正在等待 Komga 同步；保留操作 ID，稍后查询。 |
| `sync_failed` | Komga 同步失败；CBZ 不会自动回滚，本次也可能没有文件改动。文件仍与本次目标一致时，可在页面选择「重试同步」。 |
| `current_value_consistent` | 已核对 Komga 当前字段值；仍应分别查看 `analyze_verified`。 |
| `restore_needed` | 无法安全判断或继续当前文件版本；保留文件、数据库记录及备份，先调查，不应强行覆盖。 |
| `restored` | 已明确恢复原 CBZ；Komga 重新分析已排队或尝试排队，但其投影不声称已恢复。 |
| `aborted` | 准备阶段未完成且原文件未变化，本次操作已安全终止。 |

页面只显示该状态允许的操作。`POST /api/komga/edits/{operationId}/sync` 仅重试 Komga 分析和回读，不再改写文件。`POST /api/komga/edits/{operationId}/restore` 是显式恢复：必须能验证原备份且当前 CBZ 仍精确匹配本次写入版本；恢复前还会把待替换版本另存到私密备份目录。外部后续修改、路径变化或证据不足时会拒绝覆盖。所有这些接口都受管理员登录和请求保护；直接调用时使用与网页相同的管理员会话与 CSRF 流程。

API 启动时最多核对 100 条待处理操作，并且不会自动重新发起 Komga 分析。若操作仍待同步，按页面提供的动作处理。不要因为保存请求超时就用新预览再次写入；先按原操作 ID 查询，或使用原幂等键重试同一保存请求。

## 备份与故障恢复

每次实际改写都有独立的原件备份、哈希和准备记录；文件已经写入但 Komga 同步失败时，不自动回滚 CBZ。当前没有自动删除这些备份的策略，需将备份卷容量和长期保留纳入运维。备份与恢复必须同时保护 PostgreSQL 操作记录、`KOMGA_EDIT_BACKUP_ROOT` 卷及被映射的原 CBZ 文件；单独恢复其中一项会让版本证据不一致。连接凭据还依赖来源设置加密主密钥，恢复配置时也需保留对应密钥。

遇到 `restore_needed`，先停止对该作品的新编辑，记录操作 ID 和状态，在隔离副本中核对当前文件及私密备份的哈希和路径。不要删除操作目录、直接替换生产 CBZ 或把 `restore_needed` 人工改成成功状态。确认当前文件确实是本次写入版本后，使用页面提供的显式恢复入口；若页面没有可用恢复动作，应保留现场并在隔离环境制定针对该操作的恢复步骤。
