# 模块边界约束

## 目的

本文档定义项目重构期与重构后的模块职责边界。目标不是追求形式分层，而是减少规则散落、避免跨层重复实现，并让后续改动能快速判断“代码该放哪”。

## 总体原则

1. **任务领域优先**：任务状态、动作资格、命名、元数据、Komga 路径等规则应尽量收口到 domain / app，而不是继续散落在 handler、adapter、worker 和 repo 中。
2. **协议适配与业务规则分离**：输入输出适配可以靠 interface 层完成，但规则判断不能停留在这里。
3. **基础设施不拥有业务语义**：数据库、队列、文件系统实现只表达技术能力，不反向决定业务规则。
4. **异步执行不等于业务中心**：worker 负责驱动执行，不应成为“第二业务层”。

## 各层职责

### Domain

**应该做：**
- 定义任务状态与状态转换约束
- 定义 `can_retry / can_cancel / can_download / can_copy_to_komga` 等资格
- 定义进度语义
- 定义元数据清洗规则
- 定义文件名与 Komga 路径规则

**不应该做：**
- 依赖 HTTP request/response
- 依赖数据库模型或 SQL
- 依赖 Redis / 队列客户端
- 依赖模板、DOM、前端显示对象

### Application

**应该做：**
- 编排用例，例如创建任务、取消、重试、复制到 Komga、写入元数据历史
- 调用 domain 规则
- 协调 repo / queue / file storage 接口

**不应该做：**
- 处理 HTTP 参数解析与响应编码
- 直接写 SQL 或 Redis 客户端细节
- 承担页面文案与前端显示映射

### Interface（Web / API / Adapter）

**应该做：**
- 解析 HTTP 输入
- 调用 application 用例
- 将领域/应用返回值映射为页面或 API payload
- 保持 legacy 兼容所需的字段适配

**不应该做：**
- 定义新的业务规则
- 自行判断任务动作资格（除非只是消费 domain/app 已给出的统一语义）
- 把底层数据库字段直接当作最终产品语义输出

### Infrastructure

**应该做：**
- 仓储实现
- Redis Streams 队列实现
- 压缩包处理
- 文件存储
- Telegraph 下载器与外部依赖实现

**不应该做：**
- 通过技术实现细节反向定义业务流程
- 夹带页面或接口兼容语义

### Worker runtime

**应该做：**
- 取消息
- 调用应用用例或执行器
- 上报进度
- 推进状态变更
- 响应取消请求

**不应该做：**
- 复制一套任务规则判断
- 直接决定页面呈现语义

## 当前特殊约束

### legacy adapter 约束

当前项目还保留 legacy-facing 接口与日志 payload，因此允许 adapter 层存在，但必须满足：

- 只做协议兼容和字段映射；
- 不新增长期业务规则；
- 若出现“当前只有 adapter 里有的规则”，应视为待上移债务；
- 新功能默认不应优先加在 adapter 层。

### 前端约束

前端负责用户交互与展示，但：

- 不自行发明后端状态机；
- 不在多个文件重复定义同一动作资格；
- 日志页、首页、设置页的视图映射应尽量集中；
- 页面源码变更必须同步更新 bundle 产物。

## 代码放置判断问题清单

提交任何新逻辑前，先问：

1. 这是**规则**还是**协议适配**？
2. 如果换成 CLI、worker 或另一个 API，这段逻辑还成立吗？
   - 成立：应靠近 domain/app
   - 不成立：可能是 interface 层
3. 这段逻辑是否依赖 SQL、HTTP、DOM 或 Redis 客户端？
   - 是：不应放到 domain
4. 这段逻辑是否已经在别处有一份相同概念？
   - 是：优先收敛，不要再复制一份

## 禁止事项

以下行为在重构期默认禁止：

- 在 handler 中新增状态机规则
- 在 legacy adapter 中新增任务资格规则
- 在 repo 返回模型中混入前端显示文案
- 在前端多个文件里重复定义“是否显示某按钮”的复杂条件
- 在 worker 中新增与 domain/app 重复的资格判断逻辑

## 允许的过渡性例外

若为兼容历史接口，允许短期保留适配代码，但必须满足：

- 注明其过渡性质；
- 在 spec / plan / commit message 中说明原因；
- 优先选择“薄适配”而不是“把规则留在这里”。
