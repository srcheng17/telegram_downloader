# Media workspace CLI

Use the project's `mediactl` client and its administrator HTTP boundary. Read [the command guide](../../../docs/development/mediactl.md) for the relevant workflow, then check `mediactl --help` for the installed version. Prefer `--json` for safe machine results. If a command returns `unauthenticated` or `interaction_required`, direct the user to run the indicated login, credential, QR, review, or confirmation command in their **own terminal**; an AI tool PTY is not that terminal. Resume with safe status or verify commands after they finish. Never ask for passwords, API keys, 2FA values, QR material, or the session file in chat.

Read the target and its version before a write. Reuse service-provided task actions, setting versions, Komga `source_version` and `definitions_version`; on `conflict` or `edit_conflict`, re-read before changing the request. A user request that already specifies the target and action authorizes that operation; do not add a redundant approval step. If the target is ambiguous, use read-only commands to identify it before writing. After writing, read back task, setting, or Komga operation state; `file_committed` and `sync_pending` are partial states. For a lost Komga save response, retain the same edit JSON and `idempotency_key` when retrying.

Default AI output contains safe IDs, field keys, versions, counts, eligibility, status, and non-secret setting values. OCR text, adult metadata, book titles, file names, diff values, paths, upstream error bodies, and model prompts stay in the user's independent terminal. Use `workspace review`, `tasks error-review`, the `review` action under `settings ai`, `settings sources`, `settings fields`, and `settings rules`, plus `komga books review` and `komga metadata review` there. Do not invoke review commands from an AI tool. Only bring concrete content into the AI context when the user explicitly asks the AI to read or analyze it: call `workspace reveal prepare --workspace ID --revision N --kind field --id KEY` (or the smallest applicable `merged|image|candidate|record` scope), then `mediactl --json workspace reveal consume --workspace ID --revision N --ticket UUID --to-ai-context`. The second command deliberately emits the selected content into the AI context. Its ticket expires after 60 seconds, permits at most 256 KiB, is revision-bound and single-use; do not retry a stale ticket without re-reading the workspace. JSONL never permits reveal.

Use fixed CLI subcommands. Pass metadata values and JSON through `--input-json -`, a controlled input file, or `workspace attach --workspace ID --jsonl`. Some commands accept URL, query, or file path only as flags. Pass those nonsecret arguments as an argument array; with a shell-only tool, start the fixed `node .agents/skills/media-workspace-cli/scripts/run_args.mjs` command and send one JSON array line to its stdin, such as `["--json","tasks","list","--query","keyword"]`. The helper invokes `mediactl` without shell expansion. Never splice user text into a shell command or pass passwords, API keys, or 2FA through the helper. JSONL uses one `{"op":"status"}`-shaped object per line, optional `args`, and `expected_revision` on writes; it returns only safe summaries and rejects review/AI send operations. Validate opaque IDs before placing them in command arguments. `workspace image add` performs local OCR; images stay on the client. `workspace provider search` makes an external source request, and `workspace ai extract` sends confirmed text to the saved AI target; use them only when they serve the user's request. AI extraction itself needs the user's review and send confirmation in their own terminal.

Useful safe starting points are `mediactl --json auth status`, `mediactl --json overview`, `mediactl --json metadata schema`, `mediactl --json connections komga status`, and `mediactl --json komga libraries list`. `mediactl --help` and the guide contain the rest of the current command surface. Do not bypass the CLI with database access or direct CBZ writes.
